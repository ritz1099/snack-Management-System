Snack Counter Automation — Database Design

PostgreSQL · Reporting currency: INR · Money stored as NUMERIC (never float) · Receipts in blob storage

1. Entity overview

TablePurpose
officeOne row per office (Oslo, Bengaluru). Current monthly budget + its currency.
office_monthly_budgetBudget history per month, so old reports stay accurate if budgets change.
volunteerAn employee. Home office + live current_location (OSLO / BENGALURU / REMOTE / HOLIDAY) that drives assignment, plus cached fairness counters.
refillThe core lifecycle record. Single columns for assigned/committed volunteer guarantee one owner at a time.
claimLocal 1:1 mirror of the reimbursement claim sent to HR (HR is external; we keep our own copy + status).
receiptOne or more receipt images per refill (DB holds only a storage_uri).
refill_eventAppend-only audit log of every state transition (reassignment rounds, escalation, forensics).

2. ER diagram

REFILL_EVENT also references VOLUNTEER (the actor of each transition) via volunteer_id — omitted from the diagram to keep it readable; it is an FK in the DDL below.

3. Table definitions (DDL)

-- ---------- OFFICE ----------
CREATE TABLE office (
  id               VARCHAR(20)  PRIMARY KEY,                 -- 'OSL', 'BLR'
  name             VARCHAR(50)  NOT NULL,
  monthly_budget   NUMERIC(12,2) NOT NULL,
  budget_currency  CHAR(3)     NOT NULL CHECK (budget_currency IN ('NOK','INR')),
  location_tag     VARCHAR(10) NOT NULL CHECK (location_tag IN ('OSLO','BENGALURU')),
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE office_monthly_budget (
  office_id       VARCHAR(20)  NOT NULL REFERENCES office(id),
  period_month    CHAR(7)      NOT NULL,                      -- 'YYYY-MM'
  budget_amount   NUMERIC(12,2) NOT NULL,
  currency        CHAR(3)     NOT NULL CHECK (currency IN ('NOK','INR')),
  PRIMARY KEY (office_id, period_month)
);

-- ---------- VOLUNTEER ----------
CREATE TABLE volunteer (
  id                VARCHAR(20)  PRIMARY KEY,                -- company employee id (SSO)
  display_name      VARCHAR(100) NOT NULL,
  home_office_id    VARCHAR(20)  NOT NULL REFERENCES office(id),
  current_location  VARCHAR(10)  NOT NULL CHECK
      (current_location IN ('OSLO','BENGALURU','REMOTE','HOLIDAY')),
  refills_done      INTEGER      NOT NULL DEFAULT 0,   -- cached for fairness
  last_refill_at    TIMESTAMPTZ,
  created_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- ---------- REFILL (core lifecycle) ----------
CREATE TABLE refill (
  id                        BIGSERIAL PRIMARY KEY,
  office_id                 VARCHAR(20) NOT NULL REFERENCES office(id),
  status      VARCHAR(12) NOT NULL CHECK (status IN
    ('EMPTY','ASSIGNED','COMMITTED','PURCHASED','APPROVED','REIMBURSED','REASSIGNED','CANCELLED')),
  created_at                TIMESTAMPTZ NOT NULL DEFAULT now(),   -- reported empty
  reported_by               VARCHAR(20) REFERENCES volunteer(id),

  assigned_volunteer_id     VARCHAR(20) REFERENCES volunteer(id),
  assigned_at               TIMESTAMPTZ,
  commit_deadline           TIMESTAMPTZ,                 -- must accept by
  assignment_round          INTEGER NOT NULL DEFAULT 1,  -- ++ on reassign

  committed_volunteer_id    VARCHAR(20) REFERENCES volunteer(id),
  committed_at              TIMESTAMPTZ,
  purchase_deadline         TIMESTAMPTZ,                 -- must buy by

  purchase_amount           NUMERIC(12,2),
  purchase_currency         CHAR(3)     CHECK (purchase_currency IN ('NOK','INR')),
  snack_description         TEXT,
  purchased_at              TIMESTAMPTZ,
  over_budget               BOOLEAN NOT NULL DEFAULT FALSE,
  over_budget_approved_by   VARCHAR(20) REFERENCES volunteer(id),

  fx_rate                   NUMERIC(10,6),                -- purchase_ccy -> INR
  fx_reporting_currency     CHAR(3) NOT NULL DEFAULT 'INR',

  approved_at               TIMESTAMPTZ,
  reimbursed_at             TIMESTAMPTZ,

  -- status-consistency guards
  CHECK (status = 'EMPTY'   OR assigned_volunteer_id  IS NOT NULL),
  CHECK (status <> 'COMMITTED' OR committed_volunteer_id IS NOT NULL),
  CHECK (status NOT IN ('PURCHASED','APPROVED','REIMBURSED')
        OR purchase_amount IS NOT NULL),
  CHECK (status NOT IN ('PURCHASED','APPROVED','REIMBURSED')
        OR purchased_at IS NOT NULL)
);

-- ---------- CLAIM (1:1 local mirror of HR claim) ----------
CREATE TABLE claim (
  id           BIGSERIAL PRIMARY KEY,
  refill_id    BIGINT NOT NULL UNIQUE REFERENCES refill(id),   -- 1:1
  employee_id  VARCHAR(20) NOT NULL REFERENCES volunteer(id),
  amount       NUMERIC(12,2) NOT NULL,
  currency     CHAR(3) NOT NULL CHECK (currency IN ('NOK','INR')),
  description  TEXT NOT NULL,
  receipt_ref  VARCHAR(255) NOT NULL,
  status       VARCHAR(12) NOT NULL CHECK (status IN
              ('SUBMITTED','APPROVED','REJECTED','PAID')),
  hr_claim_ref VARCHAR(64),                 -- id returned by HR
  submitted_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  approved_at  TIMESTAMPTZ,
  paid_at      TIMESTAMPTZ
);

-- ---------- RECEIPT ----------
CREATE TABLE receipt (
  id          BIGSERIAL PRIMARY KEY,
  refill_id   BIGINT NOT NULL REFERENCES refill(id),
  uploaded_by VARCHAR(20) NOT NULL REFERENCES volunteer(id),
  storage_uri VARCHAR(255) NOT NULL,
  content_type VARCHAR(50),
  uploaded_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- ---------- REFILL_EVENT (append-only audit) ----------
CREATE TABLE refill_event (
  id           BIGSERIAL PRIMARY KEY,
  refill_id    BIGINT NOT NULL REFERENCES refill(id),
  from_status  VARCHAR(12),
  to_status    VARCHAR(12) NOT NULL,
  volunteer_id VARCHAR(20) REFERENCES volunteer(id),   -- actor
  note         TEXT,
  occurred_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- ---------- INDEXES ----------
CREATE INDEX idx_refill_office_status ON refill(office_id, status);
CREATE INDEX idx_refill_active_owner  ON refill(assigned_volunteer_id)
       WHERE status IN ('ASSIGNED','COMMITTED');
CREATE INDEX idx_refill_committed     ON refill(committed_volunteer_id) WHERE status = 'COMMITTED';
CREATE INDEX idx_refill_purchased    ON refill(office_id, purchased_at)
       WHERE status IN ('PURCHASED','APPROVED','REIMBURSED');
CREATE INDEX idx_volunteer_location   ON volunteer(current_location);
CREATE INDEX idx_claim_status        ON claim(status);
CREATE INDEX idx_event_refill_time    ON refill_event(refill_id, occurred_at);

4. Atomicity — how "two people can't both commit" is enforced

Ownership is a single column, and the transition is a compare-and-set UPDATE. Only the first caller wins; the second gets 0 affected rows and is rejected. Every transition also inserts a refill_event row in the same transaction.

-- Commit: only the assigned volunteer can move ASSIGNED -> COMMITTED
UPDATE refill
SET status = 'COMMITTED',
    committed_volunteer_id = assigned_volunteer_id,
    committed_at = now(),
    purchase_deadline = now() + interval '2 days'
WHERE id = $1
  AND status = 'ASSIGNED'
  AND assigned_volunteer_id = $2;   -- caller's volunteer id
-- affected rows = 1 -> commit succeeded
-- affected rows = 0 -> already taken / state changed -> reject

5. Key queries

Fairness assignment

Eligible = currently at the target office; pick fewest refills, then longest since last. FOR UPDATE SKIP LOCKED makes concurrent assignments safe.

SELECT v.id
FROM volunteer v
JOIN office o ON o.id = $1
WHERE v.current_location = o.location_tag
ORDER BY v.refills_done ASC, v.last_refill_at ASC NULLS FIRST
LIMIT 1 FOR UPDATE SKIP LOCKED;

Budget check (before filing the claim)

Sums this month's spend in the office's own currency. If false → set over_budget = true, do not auto-file; flag for office-lead approval.

SELECT
  ( (SELECT COALESCE(SUM(purchase_amount),0) FROM refill
      WHERE office_id = $1
        AND status IN ('PURCHASED','APPROVED','REIMBURSED')
        AND date_trunc('month', purchased_at) = date_trunc('month', now()))
    + $2 )                              -- new amount
  <= (SELECT monthly_budget FROM office WHERE id = $1)
  AS within_budget;

Monthly report — per-office local totals + combined INR total

Uses the FX snapshot stored per refill. A Bengaluru refill has fx_rate = 1 (already INR).

SELECT
  o.id AS office,
  COALESCE(SUM(r.purchase_amount),0) AS local_spend,
  o.budget_currency,
  o.monthly_budget,
  COALESCE(SUM(
    CASE WHEN r.purchase_currency = 'INR' THEN r.purchase_amount
         ELSE r.purchase_amount * r.fx_rate END),0) AS spend_inr
FROM office o
LEFT JOIN refill r ON r.office_id = o.id
  AND r.status IN ('PURCHASED','APPROVED','REIMBURSED')
  AND date_trunc('month', r.purchased_at) = date_trunc('month', now())
GROUP BY o.id;
-- combined INR total = SUM(spend_inr) over all offices

Timeout reassignment (scheduled job)

SELECT id, office_id, assignment_round
FROM refill
WHERE (status = 'ASSIGNED'  AND commit_deadline   < now())
   OR (status = 'COMMITTED' AND purchase_deadline < now());

6. Notes & rationale

  • Money: NUMERIC(12,2) for amounts, NUMERIC(10,6) for FX rates. No floats anywhere.
  • Currencies: per-office budget is checked in that office's budget_currency; the combined report converts everything to INR using the per-refill fx_rate snapshot taken on purchase day.
  • Receipts: stored in blob storage; receipt.storage_uri is the only thing in the DB — keeps rows small.
  • Single owner: enforced structurally (one column) + atomically (CAS UPDATE) + audited (refill_event). The status-consistency CHECK constraints keep status and owner in sync.
  • Fairness cache: volunteer.refills_done and last_refill_at are denormalized for a fast ORDER BY. Updated in the same transaction as the refill transition, so they never drift.
  • HR is external: claim is our local mirror. hr_claim_ref is the id HR returns; we poll/update claim.status when HR approves.
  • Reporting currency is fixed to INR (fx_reporting_currency default) per requirement.
